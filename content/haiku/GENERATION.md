# Дописывание хокку Claude · промпт и правила

> **Версия:** 0.1 · **Статус:** черновик; **нужно ревью Агентов 10 и 3** (тексты), 5 и 13 (где и как вызывается), 7 (что уходит в LLM) · **Дата:** 2026-11-06
> **Владелец:** Агент 16 · **Связано:** `STYLE.md`, `stopwords.yaml`, `library.yaml`, `scripts/check_haiku.py`, A25 §7 (приватность), A32 (провайдер ИИ)

## Резюме
1. Генерация нужна, когда для пользователя в библиотеке не осталось хокку, которые подходят режиму и тегам дня и ещё не показывались (`STYLE.md` §6.2).
2. В LLM уходит только **режим, грубые теги дня, сезон, показанные id и тексты хокку, образы последних 7 дней**. Никаких цифр, сырых данных WHOOP, ответов колод и меток S4/S5 (A25 §7).
3. Claude возвращает **JSON с 3 кандидатами**. Каждый проходит `check_haiku.py --candidates`. Показывается первый прошедший; если не прошёл никто — одна повторная попытка с ошибками валидатора, потом тишина (никогда не повтор).
4. Сгенерированные хокку хранятся на устройстве с пометкой `source: generated`. Лучшие (отметка «в точку») раз в неделю идут Агенту 16 и после ревью 10 и 3 попадают в библиотеку с новым `hk-` id.

---

## 1. Когда вызывать
- **Заранее, а не утром.** Утро должно работать без сети (A09 §1, A34). Поэтому генерация идёт в фоне, когда запас подходящих хокку для режима падает ниже 10 (с учётом текущего сезона и тега `any`). Результат после проверки ложится в локальный запас.
- **По месту**, если утром запас всё-таки пуст и есть сеть: один вызов с полными тегами дня, ожидание не больше 3 секунд, иначе экран без хокку.
- Вызов идёт через тонкий бэкенд (`backend/`): ключ API живёт только там, в GitHub Secrets, а не в приложении (CLAUDE.md). Модель и провайдер — по A32 и решению Агентов 5 и 13.

## 2. Вход (JSON)
```json
{
  "mode": "berezhno",
  "day_tags": ["sleep_short", "workday", "season_autumn"],
  "season": "season_autumn",
  "count": 3,
  "shown_ids": ["hk-berezhno-002", "hk-berezhno-048", "hkg-berezhno-1a2b3c4d"],
  "shown_texts": ["Ночь прошла быстро,\nа утро не торопит.\nНачни медленно."],
  "recent_images": ["dawn", "tea", "fog", "harbor"],
  "allowed_images": ["anchor", "bread", "bridge", "..."]
}
```
- `day_tags` — те же теги, что в `STYLE.md` §6.1; при фоновой генерации — только сезон (кандидаты получат `any` или сезонный тег).
- `shown_texts` — тексты, показанные пользователю за последние 90 дней (не больше 120 штук, чтобы промпт был коротким). Полную проверку на повтор делает валидатор по всей истории на устройстве.
- `allowed_images` — ключи из `images:` в `library.yaml` минус `recent_images`.

## 3. Выход (JSON)
```json
{
  "haiku": [
    {
      "id": "hkg-berezhno-5f0c9a12",
      "mode": "berezhno",
      "tags": ["sleep_short", "season_autumn"],
      "image": "bridge",
      "text": "строка 1\nстрока 2\nстрока 3",
      "syllables": [5, 7, 5]
    }
  ]
}
```
`id` — `hkg-<mode>-<8 hex>`; приложение может перезаписать его своим случайным значением. `syllables` — самопроверка модели; валидатор её не учитывает и считает заново.

## 4. Промпт

**System:**
```
Ты — Поэт-редактор приложения Health of a Titan. Ты пишешь одно утреннее хокку на русском
для экрана «Рассвет». Оно честно называет состояние человека образом и последней строкой
разворачивает его к дню. Титан в продукте — статуя и ритм, а не тело: он держит небо,
садится у моря, переводит дух.

Форма (жёстко):
- три строки, 5-7-5 слогов; слог = гласная буква (а е ё и о у ы э ю я); й, ь, ъ не считаются;
- перед ответом посчитай гласные в каждой строке по буквам и исправь, если не 5-7-5;
- без цифр, латиницы, «!», «%», эмодзи и кавычек;
- заглавная только в начале предложения; «Титан» всегда с заглавной;
- обращение на «ты» без рода: не «выспался», не «готов», не «будь мягким».

Поэтика:
- образ вместо объяснения: предмет, который можно нарисовать (камень, вёсла, иней, свеча);
- поворот (тире или точка) между образом и смыслом;
- последняя строка — приглашение, разрешение или мера на день, без морали;
- если в тегах есть сезон, в тексте есть сезонная примета; если сезона нет, сезонных примет нет;
- ключевой образ — строго из allowed_images, и он должен быть главным предметом хокку.

Голос по режимам:
- razgon (Разгон): простор и стремление без крика; приглашение к делу.
- ravno (Ровно): ритм, мера, доверие темпу; одно за другим.
- berezhno (Бережно): разрешение и опора; отдых — тоже часть силы; так же красиво, как Разгон.

Честность о сигналах (называй образом, без цифр и причин):
- sleep_short: ночь прошла быстро / сна было мало;
- sleep_good: сон был глубоким / ночь была щедрой;
- recovery_low: колодец мелок / ручей обмелел / огонь небольшой, но греет;
- recovery_high: колонны прямы / прилив / конь бьёт копытом;
- strain_high: вчера был путь неблизкий / вчерашний груз.

Никогда:
- диагнозы, симптомы, болезни, лекарства, врачи, боль, метрики (пульс, норма, процент,
  восстановление, стресс, гормоны) и утверждения о теле и здоровье;
- оценка тела (вес, фигура, форма, мышцы, худеть);
- стыд, вина, давление, сравнение с другими (должен, надо, нужно, лень, провал, плохо, хуже,
  соберись, лучше всех);
- токсичный позитив и обещания (ты же титан, ты справишься, через не могу, через боль,
  гарантия, навсегда, станешь);
- смерть, кровь, яд, утопление, бездна, безнадёжность и любые образы конца, падения,
  «дна», «тонкого льда», «держись из последних сил»;
- ложная срочность; чужие строки, цитаты и переделки известных хокку и песен.

Ответ — только JSON по схеме, без пояснений.
```

**User:**
```
Напиши {count} разных хокку.
Режим: {mode}. Теги дня: {day_tags}. Сезон: {season}.
Можно использовать только эти образы: {allowed_images}. Не используй образы: {recent_images}.
Каждый кандидат — с другим образом.
Теги кандидата — только из тегов дня; если хокку подходит любому дню этого режима, тег ["any"].
Эти хокку человек уже видел; не повторяй их строки, образы фраз и концовки:
{shown_texts}
Схема ответа: {"haiku":[{"id":"hkg-{mode}-<8 hex>","mode":"{mode}","tags":[...],
"image":"...","text":"строка1\nстрока2\nстрока3","syllables":[5,7,5]}]}
```

## 5. Автоматические проверки
Бэкенд (или приложение) сохраняет ответ в `out.json`, вход — в `request.json` и запускает:
```
python3 scripts/check_haiku.py --candidates out.json --request request.json
```
Валидатор отклоняет кандидата, если:
1. не 5-7-5 по гласным, не три строки, есть цифры, латиница, «!» или «%»;
2. нарушены заглавные или «титан» со строчной;
3. `mode` не равен запрошенному; тег не из списка, не истинен сегодня или противоречит режиму (A09 §2);
4. `image` не из `images:` библиотеки или был за последние 7 дней (`recent_images`);
5. текст или **любая строка** совпадает с библиотекой или с `shown_texts` (после нормализации);
6. есть слово из `stopwords.yaml → errors` (диагнозы и медицина, оценка тела, стыд и давление, токсичный позитив и обещания, кризисные слова).

Слова из `stopwords.yaml → warnings` не отклоняют кандидата. Такие хокку показываются, но попадают в еженедельную выборку для человека первыми.

В приложении (Kotlin) те же проверки повторяет порт валидатора на устройстве (задача Агента 13). Источник правил один: `stopwords.yaml` и списки в `check_haiku.py`.

## 6. Что делать с результатом
| Ситуация | Действие |
|---|---|
| ≥ 1 кандидат прошёл | показать или положить в запас первый прошедший; остальных тоже в запас |
| никто не прошёл | один повтор: тот же промпт плюс строка «Исправь ошибки валидатора: …» |
| повтор не прошёл / нет сети | хокку сегодня нет; событие `haiku_generation_failed` в локальный лог |
| пользователь отметил «в точку» / «мимо» | сохраняется рядом с id; раз в неделю выборка (все «в точку», все с предупреждениями, 10 % случайных) уходит Агенту 16 на ревью |

**Приватность:** в запросе нет данных о здоровье, кроме грубых тегов (`sleep_short` и т. п.). Тексты показанных хокку не персональные. Нужно подтверждение Агента 7, что теги дня можно отправлять провайдеру LLM без отдельного согласия (A25 §7: сырые S4/S5 в LLM не уходят; теги — производные коды).
