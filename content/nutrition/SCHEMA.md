# Система питания — схема контента

> **Артефакт:** A41 · **Проверка:** `python3 scripts/check_nutrition.py` · **Профиль особенностей:** `content/profile/` (общий с тренировками A40)
> **Ведущий:** Агент 12 · **Вето:** Агент 3 (медицина) · **Ревью:** Агент 10 (слова о еде, РПП), Агент 7 (данные здоровья) · Статус: черновик.

## 1. Что где лежит

Система питания — это **конфигуратор**: закрытые справочники + правила + детерминированный движок. Claude не придумывает план с нуля, а собирает и описывает его из этих кубиков; всё, что он предложил, проходит тот же валидатор.

| Слой конфигуратора (A41 §7) | Файл | Что задаёт |
|---|---|---|
| 0. Профиль — жёсткие исключения | `content/profile/constraints.yaml` | аллергены, непереносимости, тип питания, физиология, этап жизни, медицинские флаги, травмы |
| 1. Уровень | `methods.yaml → levels` | `base` «Основа», `structured` «Опора», `precise` «Точность» |
| 2. Цель | A41 §4.3 (в движке — перечисление `goal`) | `energy`, `training_fuel`, `recovery`, `habits`; целей по весу нет |
| 3. Методика | `methods.yaml → methods` | техника, уровень доступа, доказательность A04, что меняет в плане |
| 4. Шаблон дня | `templates.yaml → templates` | уровень × класс нагрузки → слоты приёмов, тарелки, методики |
| 5. Модификаторы | `rules.yaml` + `templates.yaml → overlays` | режим дня A09, сон и нагрузка WHOOP, контекст, привычки |
| 6. Блюда | `meals.yaml` | блюдо = компоненты + порции ладонью + слоты + контекст + замены |
| 7. Порции | `templates.yaml → plates` + `components.yaml → per` | ладони и горсти; граммы — только диапазоном и по желанию |
| — | `stopwords.yaml` | что продукт не говорит (диеты-чудеса, «детокс», стыд, оценка тела, дозы) |
| — | `_tests/profiles.yaml`, `_tests/candidates.yaml` | профили для проверки фильтра и примеры генерации Claude |

Все списки **закрытые**: новое значение появляется только добавлением в файл, и валидатор проверяет ссылки.

## 2. Компоненты (`components.yaml`)

### 2.1 Поля

| Поле | Обязательно | Значения |
|---|---|---|
| `id` | да | `snake_case`, уникален, не переименовывается |
| `ru` | да | название для экрана |
| `group` | да | из `groups`: `protein_animal`, `protein_plant`, `dairy`, `grain`, `starchy_veg`, `legume`, `vegetable`, `fruit`, `nut_seed`, `fat_oil`, `condiment`, `drink`, `ready` |
| `role` | да | роль на тарелке из `roles`: `protein`, `starch`, `veg`, `fruit`, `fat`, `extra`, `drink` |
| `allergens` | да | коды из `profile.allergens`; `[]`, если нет. Если есть `wheat`, обязателен `gluten` |
| `may_contain` | нет | «может содержать» (перекрёстный контакт, типичная маркировка) |
| `origin` | да | происхождение из `profile.origins` (`meat_pork`, `dairy`, `egg`, `honey`, `alcohol`…); растительное — `[]` |
| `lactose` | да | `none`, `low`, `high` |
| `tags` | да | свободные метки поиска; особые: `spicy` (фильтр «не ем острое»), `soft`, `gf_alt`, `nut_free_alt`, `plant_alt` |
| `per` | да | `{p, c, f, fib}` — граммы белка, углеводов, жиров, клетчатки на **одну порцию ладонью**, ±25 %, USDA FDC |

### 2.2 Почему нет калорий

Поля `kcal` нет намеренно: вето Агента 3 (A19 §7 №1) и D-010. Энергия — не число продукта по умолчанию. Если основатель и Агент 3 разрешат методику `energy_reference` (A41 вопрос 1), диапазон считается из `p/c/f` движком, а не хранится в справочнике.

### 2.3 Порции ладонью

| Роль | Одна порция | Примерно |
|---|---|---|
| белок | ладонь (толщина и площадь) | 20–30 г белка |
| крахмал, фрукт | сложенная горсть | 20–30 г углеводов |
| овощи | кулак | — |
| жир | большой палец | 7–12 г жира |

`n` в блюде — число таких порций для «рабочей» тарелки (`moderate`). Движок пересчитывает только крахмал и фрукт по тарелке дня; белок и безопасность не трогает.

## 3. Блюда (`meals.yaml`)

| Поле | Обязательно | Значения |
|---|---|---|
| `id` | да | `M` + три цифры, уникален навсегда; снятое блюдо — `retired: true` |
| `ru` | да | название без оценок («полезный», «вредный» запрещены стоп-словами) |
| `levels` | да | подмножество `base`, `structured`, `precise` |
| `slots` | да | из `templates.yaml → slots` |
| `plate` | да | из `templates.yaml → plates` |
| `components` | да | `[{c: <component id>, n: <порции>}]`, ≥ 1 |
| `context` | да | `home`, `office`, `restaurant`, `fastfood`, `travel`, `airport`, `gym`, `outdoor` |
| `prep_min` | да | 0–120 |
| `swaps` | да | `{компонент: [замены]}`; замена должна иметь ту же роль на тарелке |
| `tags` | да | закрытый список `meal_tags` в начале файла |
| `allergens`, `may_contain`, `diets` | да | **объявляются для людей, но проверяются**: валидатор выводит их из компонентов и падает при расхождении |

Метка диеты выводится так: блюдо подходит диете, если ни один компонент не имеет исключённого ею происхождения или аллергена; для `kosher` — ещё и нет одновременно мяса и молочного; для `gluten_free` — и нет `gluten` в `may_contain`.

## 4. Шаблоны дня (`templates.yaml`)

- `plates` — доли тарелки (сумма 1,0) и порции ладонью для одного основного приёма: `base`, `easy`, `moderate`, `hard`, `snack`.
- `slots` — приёмы пищи с **якорями**, а не часами: от подъёма, отбоя (A09 §7a) и начала тренировки.
- `load_classes` — `rest`, `light`, `moderate`, `hard`, `long`; приходит из тренировочной системы (A40) и уточняется фактом WHOOP.
- `templates` — для каждого уровня каждый класс нагрузки покрыт **ровно одним** шаблоном (проверяется).
- `overlays` — наложения поверх шаблона (`OV-gentle`, `OV-sick`, `OV-travel`, `OV-no-time`, `OV-ed-care`, `OV-safe`): только упрощают и делают безопаснее, никогда не повышают уровень, тарелку или числа.

## 5. Методики (`methods.yaml`)

| Поле | Значения |
|---|---|
| `from_level` | минимальный уровень |
| `default` | `on`, `off`, `optional` |
| `opt_in` | `true` — включает только сам человек |
| `requires` | данные профиля, без которых методика не работает (например, `body_mass_kg`) |
| `evidence` | шкала A04: A — метаанализы и руководства, B — РКИ и сильные когорты, C — малые или механистические, D — практика и форма подачи |
| `source` | источник; `[проверить]` — сверить Агенту 3 до релиза |
| `numbers` | `none`, `time_only`, `grams_range`, `kcal_range` — что методика показывает |
| `status: blocked` + `blocked_by` | не показывается, пока не принято названное решение |

`excluded` — то, чего в HoT нет ни на каком уровне (очень низкокалорийные диеты, голодание больше суток, цели по весу, лечебные диеты, дозировки). Тексты из `excluded` стоп-словами не проверяются: они называют то, чего мы не делаем.

## 6. Правила (`rules.yaml`)

- `facts` — что движок читает (режим дня, флаги, сон, нагрузка, профиль) и класс чувствительности.
- `effects` — закрытый список действий правила.
- `rules` — `id`, `when` (выражение над фактами), `then` (только действия из `effects`), `why_ru` (объяснение человеку), `evidence`, опционально `a19:` (ссылка на N01–N20).
- Порядок = приоритет: безопасность → режим дня → сон → нагрузка → контекст → привычки. Первое правило, которое ограничивает или скрывает, главнее всех ниже.
- `hints` — тексты подсказок `H-*`; `N01…N20` — тексты A19 §4.

## 7. Стоп-слова (`stopwords.yaml`)

Проверяются все тексты для человека: `ru`, `what_ru`, `why_ru`, `note_ru`, `hints`, подписи профиля, а также каждое блюдо, сгенерированное Claude.
- `errors` — отклоняется: диеты-чудеса («детокс», «жиросжигание», «чистая еда», «минус 5 кг»), стыд и оценка тела («вредное», «срыв», «заслужил», «лишний вес», «фигура», «сила воли»), медицина и дозы («лечебный», «диагноз», «мг», «иммунитет»).
- `warnings` — допускается, но читает человек (Агент 10 или 3): «калории», «диета», «вес», «голодание», «нельзя».

## 8. Генерация Claude по правилам

Когда библиотеки не хватает (редкое сочетание исключений, просьба «хочу что-то новое», ресторанное меню по фото), Claude **предлагает кандидатов**, а движок решает.

**Что уходит в Claude:** уровень, слот, тарелка дня, контекст, коды исключений (`exclude_allergens`, `exclude_origins`, `lactose_max`, `exclude_tags`), `safe_mode: true/false`, список разрешённых `component id` (уже отфильтрованный), до 5 последних блюд. Названия медицинских флагов, вес, история еды не уходят (Агент 7).

**Что Claude возвращает** — JSON-массив блюд по схеме §3 (без `id`, валидатор присваивает `G-…`), только из разрешённых компонентов.

**Валидатор** (`check_nutrition.py --candidates out.json --profile <id или файл>`):
1. схема и закрытые списки; 2. все компоненты есть в справочнике; 3. аллергены, `may_contain`, происхождение, лактоза, теги пересчитываются из компонентов и проходят фильтр профиля; 4. объявленные `allergens` совпадают с выведенными; 5. стоп-слова; 6. уровень не выше потолка профиля; 7. при `hide_numbers` в тексте нет цифр граммов. Не прошёл — блюдо не показывается, вместо него — тарелка из библиотеки.

При `anaphylaxis` генерация отключена (`no_unlabeled_generation`): только проверенные блюда библиотеки.

## 9. Тесты

`_tests/profiles.yaml` — профили-примеры (орехи с анафилаксией, целиакия, без глютена, лактоза, белок молока, веган, веган + без глютена + орехи, халяль, кошер, рыба и морепродукты, РПП, почки, диабет, беременность). Для каждого валидатор проверяет:
1. ни одно разрешённое блюдо (после замен) не содержит запрещённого;
2. на каждый основной слот (завтрак, обед, ужин) остаётся не меньше `min_options` блюд;
3. режим, потолок уровня, скрытые цифры и запрещённые методики совпадают с ожиданием;
4. `must_reject_raw` — блюда, которые **без замен** обязаны быть отклонены (доказывает, что фильтр не пустой).

`_tests/candidates.yaml` — примеры ответов Claude с ожидаемым итогом `accept` или `reject`.

## 10. Правила изменения

- Новый компонент или блюдо — добавлением, `id` не переиспользуются.
- Методики, медицинские тексты, `excluded` — только с ревью Агента 3; тексты о еде и теле — Агента 10; бренды и хранение — Агента 7.
- Изменение позиции по калориям (методика `energy_reference`, окно питания `tre_window_8_10`) — только решением основателя после ревью 3 и 10 (A41 §3).
- Перед коммитом: `python3 scripts/check_nutrition.py` без ошибок.
