# Профиль особенностей пользователя — схема

> **Файл данных:** `content/profile/constraints.yaml` · **Проверка:** `python3 scripts/check_nutrition.py` (часть «profile»)
> **Кто пользуется:** питание (A41, `content/nutrition/`) и тренировки (A40, ветка `claude/training-system`). Один профиль на оба движка.
> **Ревью:** медицина — Агент 3 (вето), слова о еде и теле — Агент 10, хранение и согласие — Агент 7. Статус: черновик Агента 12.

## 1. Зачем

Особенности человека (аллергия, тип питания, беременность, травма колена, диабет) — это **условия, которые проверяются раньше всего остального**. Ни уровень, ни цель, ни Claude не могут их обойти. Профиль — закрытый список кодов `snake_case`: экран настройки, детерминированный движок и генерация Claude видят одни и те же коды.

Профиль **не ставит диагнозов**. Медицинский флаг — это то, что человек сам о себе сказал; он переключает продукт в безопасный режим и ведёт к врачу, а не «лечит».

## 2. Разделы и что они делают

| Раздел | Коды (примеры) | Сила | Что делает в питании | Что делает в тренировках |
|---|---|---|---|---|
| `allergens` | `peanut`, `tree_nut`, `gluten`, `wheat`, `milk`, `egg`, `fish`, `crustacean`, `mollusc`, `soy`, `sesame`, `celery`, `mustard`, `sulphite`, `lupin`, `coconut` | **жёсткий фильтр** | блюдо с аллергеном не попадает в план, даже после замены | — |
| `allergy_severity` | `avoid`, `allergy`, `anaphylaxis` | уточняет фильтр | «может содержать»: `avoid` — можно с пометкой, `allergy` и `anaphylaxis` — исключено; при `anaphylaxis` — предупреждение для ресторанов, без генерации блюд без маркировки | — |
| `intolerances` | `lactose`, `gluten_sensitive`, `caffeine`, `spicy`, `fodmap` | фильтр или смягчение | `lactose` — убирает компоненты с высокой лактозой; `caffeine` — кофейный рубеж на 2 ч раньше; `fodmap` — только маршрут к специалисту | — |
| `diets` | `omnivore`, `pescatarian`, `vegetarian`, `vegan`, `halal`, `kosher`, `gluten_free`, `no_pork`, `no_beef`, `no_alcohol` | **жёсткий фильтр** | исключает компоненты по происхождению (`origin`); у `kosher` ещё правило «мясо не с молочным» | — |
| `dislikes` | любые `id` из `components.yaml`, до 20 | мягко | снижает приоритет блюда, безопасность не трогает | — |
| `physiology` | `age_band`, `body_mass_kg`, `height_cm`, `sex_for_ref`, `menstrual_cycle`, `shift_work`, `chewing_swallowing` | настройка | вес нужен только для диапазонов граммов на уровнях «Опора» и «Точность»; сменная работа — шаблоны от якорей сна | возраст и сменная работа |
| `life_stage` | `pregnancy`, `lactation`, `postpartum_6m` | **безопасный режим** | уровень не выше «Основы», запрет окон питания и граммов, подсказки H-PREG/H-LACT | программы нет, маршрут к врачу |
| `injury_regions` + `injury_status` + `movement_limits` | `knee`, `lower_back`, `shoulder`…; `acute`, `recovering`, `chronic_stable`; `no_impact`, `no_overhead`… | для тренировок | питание игнорирует | исключение упражнений, при `acute` — только к врачу или физиотерапевту |
| `medical_flags` | `ed_history`, `diabetes`, `kidney`, `celiac`, `heart_bp_meds`, `gi_disease`, `bariatric`, `anticoagulants`, `other_chronic`, `underweight_reported` | **безопасный режим** | ограничение уровня, запрет методик, скрытие цифр, «обсуди с врачом» | маршрут к врачу перед интенсивностью |

### 2.1 Удобные коды травм для тренировок

Тренировочный движок (A40) принимает травму как пару «регион + статус» и ограничения движения. Чтобы экран и генерация говорили одними словами, ниже — **готовые составные коды**; каждый разворачивается в регион, статус и ограничения:

| Код | Разворачивается в |
|---|---|
| `knee_injury` | `knee` + `recovering` → `no_impact`, `no_deep_knee_flexion` |
| `lower_back_pain` | `lower_back` + `chronic_stable` → `no_loaded_spinal_flexion` |
| `shoulder_injury` | `shoulder` + `recovering` → `no_overhead` |
| `neck_pain` | `neck` + `chronic_stable` → `no_overhead` |
| `wrist_pain` | `wrist_hand` + `recovering` → без упоров на ладони (уточняет A40) |
| `ankle_injury` | `ankle_foot` + `recovering` → `no_impact` |
| `hip_pain` | `hip` + `chronic_stable` → `no_deep_knee_flexion` |
| `pregnancy` | `life_stage.pregnancy` → программы нет, маршрут к врачу; после разрешения врача — `no_floor_work` (после I триместра), `no_breath_hold`, `no_high_intensity` |
| `hypertension` | `medical_flags.heart_bp_meds` → `no_breath_hold`, `no_high_intensity` до отметки «врач разрешил» |
| `osteoporosis_reported` | `medical_flags.other_chronic` → `no_impact`, `no_loaded_spinal_flexion` |

Составные коды лежат в `constraints.yaml → injury_presets`. Окончательный список упражнений по каждому коду — в A40 (Агенты 12 и 3), здесь только словарь.

## 3. Свёртка профиля в режим

Движок сворачивает все отметки в один **режим** и один **потолок уровня**. Порядок — первый сработавший главнее:

```
ed_history или сигналы РПП (A19 §6.3)  → mode = ed_care,     уровень ≤ «Основа», цифры скрыты
underweight_reported                   → mode = ed_care,     цифры скрыты
любой life_stage или medical с safe     → mode = safe,        потолок из флага, H-MED / H-PREG
только celiac / anticoagulants          → mode = filter_only, фильтр + H-MED, уровень не меняется
ничего                                 → mode = normal
```

Потолок уровня = минимум из выбранного пользователем и всех `max_level` флагов. Запрещённые методики = объединение всех `forbid_methods`. Исключения аллергенов и происхождения = объединение всех отметок (вегетарианство + халяль работают вместе).

## 4. Порядок применения в конфигураторе

1. **Жёсткие исключения профиля** (аллергены → происхождение → лактоза → теги) — до выбора уровня и шаблона.
2. Режим и потолок уровня.
3. Запрещённые методики вычёркиваются из шаблона дня.
4. Только потом уровень, цель, шаблон, блюда, порции (A41 §7).

Если после фильтра на слот остаётся меньше трёх блюд, движок сначала пробует **замены** (`swaps` в блюде), затем блюда соседнего уровня, затем показывает универсальную тарелку из разрешённых компонентов. Он никогда не ослабляет фильтр.

## 5. Хранение и согласие (Агент 7)

- Класс **S4** (A25 §6): SQLCipher на телефоне, не в логах, аналитике, пушах и виджетах.
- **Отдельное явное согласие** на одном экране, по категориям, до первого поля. Халяль и кошер могут раскрывать религию — тоже S4.
- В Claude уходят **только коды исключений** (`[peanut, tree_nut]`, `vegan`) и `safe_mode: true`; названия медицинских флагов не уходят.
- Синхронизация в облако — отдельное согласие. Удаление — по категории и целиком. Экспорт — да.
- Дисклеймер под фильтром аллергенов (`storage.disclaimer_ru`) показывается всегда.

## 6. Правила изменения

- Новый код — только добавлением в `constraints.yaml`; старые коды не переименовываются (на них ссылаются блюда, правила и A40).
- Медицинские флаги и `life_stage` меняются только после ревью Агента 3; подписи — после Агента 10; категории хранения — после Агента 7.
- `python3 scripts/check_nutrition.py` должен проходить без ошибок.
