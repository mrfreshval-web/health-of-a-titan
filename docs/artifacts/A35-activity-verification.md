# A35 · Активность, тренировки, шаги, стресс и сверка плана с фактом · v0.1

Авторы: Агент 9 (носимые устройства), Агент 3 (наука), Агент 12 (тренер). Дата: 2026-11-06. Статус: решение принято (D-024): WHOOP-активность и шаги телефона через Health Connect — обе части обязательны в MVP. Ревью Агентов 10, 7, 5, 13.

Исходное условие: Pixel Watch основатель не носит. Источники в MVP: WHOOP (API и то, что он пишет в Health Connect) и сам телефон (шаги).

## Резюме
- Большую часть активности WHOOP уже отдаёт через API. Новые подключения не нужны.
- **Тренировки:** вебхук `workout.updated`. В нём вид спорта, начало и конец, strain, средний и максимальный пульс, kJ, дистанция и минуты в каждой пульсовой зоне. По этим данным видно, была ли тренировка, сколько длилась и какой была по интенсивности [Факт: developer.whoop.com/docs/developing/user-data/workout].
- **Шаги:** с 23.09.2026 есть `step_count` за цикл WHOOP, то есть за сутки [Факт: community.whoop.com/t/16424]. Шаги по часам даёт только телефон через Health Connect.
- **Силовые:** видим, что тренировка была, её длительность и пульс. Подходы, повторы и веса пользователь вводит в нашем таймере или отмечает сам.
- **Стресс в моменте в MVP не измеряем.** Stress Monitor есть только в приватном API WHOOP, а пульса в течение дня в открытом API нет. Вместо этого считаем «напряжение дня» из самоотчёта, нагрузки и ночного отклика HRV и пульса покоя.
- **Принцип — доверие, а не контроль.** Нагрузку считаем по данным браслета, это вопрос безопасности. Исполнение плана считаем по отметке пользователя. Главный сигнал — «сделал больше, чем позволял режим».
- **Рекомендация:** WHOOP-активность входит в MVP, это ≈ 2–2,5 дня Агента 13. Health Connect берём только для шагов телефона и только как Should из запаса, ≈ 1–1,5 дня. Pixel Watch — после MVP.

## 2. Health Connect
- **WHOOP → HC.** WHOOP пишет туда сон, пульс покоя, частоту дыхания, SpO₂ и кардиотренировки. С мая 2026 там появились шаги, но с задержкой до 2 суток [Факт, вторичный]. Всё это есть и в API, причём быстрее. **Для данных WHOOP HC не нужен.**
- **Телефон → HC.** Встроенный счётчик шагов работает на Android 14+ с SDK Extension ≥ 20, Pixel 9 Pro XL подходит. Счёт начинается только после первой выдачи `READ_STEPS`. Источник определяем через `getCurrentDeviceDataSource()` и не хардкодим [Факт: developer.android.com].
- **Механика.** Уведомлений о новых данных нет, только опрос. Фоновое чтение идёт через WorkManager с ограничениями Doze. Чтобы не было дубля, из HC берём **только шаги телефона**, отфильтрованные по data origin.
- **Стресса, EDA и Body Response нет** ни в HC, ни в Google Health API [Факт].
- Поддержка legacy Fitbit Web API закончилась 30.09.2026. Замена — Google Health API. Это кандидат после MVP вместе с Pixel Watch.

## 4. Сверка плана с фактом (Агент 12)

Тренировку WHOOP сопоставляем с `TrainingSession`, если она попадает в слот плана ±3 ч. Если слота нет — с сессией того же дня. Пороги — [Оценка], пересмотр на 30-й день.

| Пункт плана | Сигнал | Автоподтверждение | Точность |
|---|---|---|---|
| Силовая | WHOOP workout + наш таймер | длительность ≥ 60 % плана | факт: высокая; объём: самоотчёт |
| Zone 2 | `zone_durations` | ≥ 60 % в зонах 1–2 и ≥ 70 % длительности | средняя–высокая |
| Интервалы | зоны 4–5, `max_heart_rate` | ≥ 50 % рабочей части в зонах 4–5; иначе «записал как Zone 2» | средняя; короткие интервалы — только «изменено» |
| Ходьба, бег | workout, шаги телефона (Should) | ≥ ~80 шагов в минуту в окне | средняя |
| Шаги дня | `step_count` | цель — личная медиана | средняя |
| Перерывы в сидении | шаги телефона (Should) | только мягкое напоминание | низкая |
| Отбой | WHOOP sleep | ±30 мин | высокая |
| Еда, кофе, практики | самоотчёт | — | — |

**Правила доверия** (тексты — с ревью Агента 10):
1. **Три статуса пункта:** «✓ подтверждено WHOOP», «✓ отмечено тобой», «⇄ изменено». Все три засчитываются в EXE как выполнение.
2. **Нагрузку** (TRL, TRIMP) считаем по браслету. **Исполнение плана** считаем по отметке пользователя.
3. **Отметка есть, а данных WHOOP нет.**
   - Браслет не носили (`percent_recorded` низкий или `step_count` = null): тихо ставим «без браслета».
   - Браслет был на руке: один нейтральный вопрос вечером, не чаще раза в неделю. Счётчиков несовпадений нет.
4. **Сделал больше, чем позволял режим:** утром учитываем это в режиме без оценки: «Вчера было интенсивнее плана — учёл».
5. **Без браслета:** отметка, длительность и RPE. Шаги телефона частично подтверждают ходьбу.
6. **Внутренняя метрика** — доля автоподтверждённых сессий. Если она низкая, подсказываем «надень браслет на силовые».

## 5. Решение по источникам

| Сигнал | Источник | MVP |
|---|---|---|
| Тренировка, зоны, пульс, strain, kJ | WHOOP API + вебхук | **да** (в памяти, R-11) |
| Шаги за сутки, Day strain | WHOOP API cycle (опрос) | **да** |
| Сон: начало и конец | WHOOP API | да (уже есть) |
| Шаги телефона по минутам | HC, телефон | **Should** |
| Данные WHOOP через HC | HC, WHOOP | нет (дубль) |
| Пульс, HRV днём, cEDA | Pixel Watch | после MVP |
| Подходы, повторы, RPE, пик напряжения | таймер и самоотчёт | да (A19, A25) |
| Stress Monitor WHOOP | приватный API | нет (запрещено) |

Разрешения HC (если делаем Should):
- `READ_STEPS`;
- `READ_HEALTH_DATA_IN_BACKGROUND`;
- экран обоснования доступа (privacy rationale).
