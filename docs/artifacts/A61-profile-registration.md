## Резюме

- **Аккаунта в MVP нет.** Вход — это подключение WHOOP: Worker и сейчас узнаёт человека по WHOOP `user_id` (allowlist, сессия устройства). Своих логинов, паролей и почты на сервере нет, и это лучшая минимизация данных. Защита от потери телефона — зашифрованный файл экспорта (D-019). Вход через Google добавляем на этапе тестеров и только для облачного бэкапа, по желанию.
- **Профиль «Я»** — одно место для фактов о человеке. Почти всё выводится из данных (D-027): имя, рост и максимальный пульс берём из WHOOP, ритм — из сна и телефона. Вручную вводятся три вещи: **род обращения, год рождения, пол для расчётов**. Каждую спрашиваем в момент, когда она даёт пользу.
- **Род обращения и пол для расчётов — два разных поля.** Первое определяет, как мы говорим с человеком, второе — какие формулы считаем. Если их склеить, то при любом расхождении мы ошибёмся либо в обращении, либо в расчёте.
- **Тексты пишем нейтрально, формы «он» и «она» добавляем точечно.** У ключа строки нейтральная форма обязательна, формы `m` и `f` — по желанию. «Не указано» всегда даёт нейтральную форму. Сейчас под правку ≈ 20 строк в коде и YAML, работы ≈ 1,5 дня.
- **Настройки под правым кружком** (D-038) — восемь групп. Наверху карточка «Ты» и «Помощь» (112 · 911, 2 тапа, D-029), внизу — скрытый раздел «Для разработчика» (Y7).

## 1. Регистрация и вход

### 1.1 Нужен ли аккаунт

| Вариант | Что даёт | Чего стоит | Вывод |
|---|---|---|---|
| **А. Без аккаунта, вход = WHOOP** | 0 новых шагов. На сервере нет почты и пароля. Личность уже есть: WHOOP `user_id` → сессия `hs1.<user_id>…` в Worker (`backend/edge`) | после потери телефона данные пропадут, если нет экспорта | **MVP: да** |
| Б. Вход через Google (Credential Manager) | облачный бэкап и второе устройство, сброс без потери | сервер хранит Google `sub` и зашифрованный бэкап. Нужны согласие и политика удаления (ревью 7). ≈ 2–3 дня | **этап тестеров, только по желанию** |
| В. Вход по почте (ссылка или код) | работает без Google | почтовый сервис, письма, антиспам, хранение почты. Ничего не даёт сверх Б | **нет** |
| Г. Аккаунт HoT обязателен | привычно для рынка | противоречит local-first (D-019) и минимизации данных. Регистрация до первой ценности снижает удержание (Duolingo перенёс её позже и получил ≈ +20 % DAU, A48 [2]) | **нет** |

**Почему вход = WHOOP.** Без WHOOP у продукта нет данных о дне. Значит, подключение WHOOP — уже обязательный шаг, и он же даёт стабильный идентификатор. Отдельная регистрация была бы вторым шагом про то же самое.

**Без WHOOP** приложение работает в демо-режиме на примерах данных (Health Connect даёт только шаги, D-024). Профиль и настройки в нём работают, план дня — нет.

**Бэкап в MVP.** В «Данные и приватность» есть пункт **«Сохранить копию»**: файл, зашифрованный паролем, который человек придумывает сам. Его можно сохранить в «Файлы», на Google Диск или в Telegram, восстановление — из того же раздела. Android Auto Backup не подходит: ключ SQLCipher живёт в Keystore и не переносится, поэтому восстановленная база не откроется (проверить Агенту 5).

## 2. Профиль «Я»

**Принцип:** «сначала данные, потом вопрос» (D-027). У выведенного значения есть подпись источника, ручная правка побеждает вывод. Ни одно поле не обязательно для работы «Сегодня».

### 2.2 Почему род обращения и пол для расчётов — разные поля

| | Род обращения | Пол для расчётов |
|---|---|---|
| Вопрос | Как с тобой говорить? | Какую формулу считать? |
| Влияет на | окончания слов («ты отметил / отметила / отмечено») | VO₂max и фитнес-возраст (HUNT), справочные диапазоны |
| Если не указано | нейтральные формы, всё работает | фитнес-возраст диапазоном, справочные тексты общие |
| Чувствительность | низкая (S2) | данные о здоровье (S3), в Claude не уходит |
| Когда расходятся | трансгендерный или небинарный человек; человек, которому привычнее нейтрально; человек, который не хочет называть пол, но хочет точный расчёт | |

**Агент 10:** выбор рода — вопрос комфорта, а не анкеты. Формулировка «Как к тебе обращаться», а не «Твой пол». Вариант «не важно» равноправен с остальными.
**Агент 3:** пол в расчётах — переменная модели, не идентичность. Подпись: «Пол для расчётов (формулы пульса и фитнес-возраста)». Этап жизни (беременность, кормление) и отметка цикла **не зависят** от выбранного пола: они доступны всем по выбору человека.

### 2.3 Медфлаги и вето (Агенты 3 и 10)

| Правило | Кто |
|---|---|
| Флаг — то, что человек **сказал сам**. Продукт его не выводит и не называет состоянием. Подпись категории — «Состояния по словам врача или твоим» | 3 |
| Свёртка в режим (SCHEMA §3): `ed_history`, `underweight_reported` → `ed_care`. Беременность, кормление, медфлаги → `safe` | 3 |
| При `ed_care`, беременности, кормлении и медфлагах A41 §6 цель по весу недоступна, вес и талия не показываются (D-043) | 3, 10 |
| `ed_care` от сигналов (SCOFF ≥ 2, NR-51, слова в чате) включается без галочки. Снять его — только после 14 дней без сигналов, текст пишет Агент 10 | 10 |
| Бета-блокаторы (`heart_bp_meds`) и `SICK` → фитнес-возраст скрыт (A52) | 3 |
| Удаление по категории и целиком, одна кнопка. После удаления режим пересчитывается сразу | 7 |
| В Claude уходят только коды исключений и `safe_mode` (`UserConstraints.llmCodes()`), названия флагов не уходят | 7 |

**Перенос из кода:** экран `NutritionProfileScreen` («Я › Еда и тело») становится разделом профиля **«Тело и здоровье»**. Уровень еды переезжает в «Ступени». `TrainingProfile` собирается из того же `UserConstraints` плюс скрининг и «врач разрешил».

## 4. Род в текстах

### 4.1 Механизм

| Часть | Решение |
|---|---|
| Значение | `enum class AddressForm { M, F, N }`. `N` — по умолчанию и для «не указано». Те же три значения, что у Android `GrammaticalInflectionManager` (API 34: MASCULINE / FEMININE / NEUTRAL), чтобы потом перейти на `strings.xml` с квалификаторами `-masculine` / `-feminine` / `-neuter` |
| Строка в коде | `data class G(val n: String, val m: String = n, val f: String = n) { fun of(a: AddressForm) = when (a) { M -> m; F -> f; N -> n } }`. **`n` обязательна**: нейтральная форма — основа строки, `m` и `f` — уточнения |
| Где берётся форма | Compose: `LocalAddressForm` (CompositionLocal из `ProfileSettings`). Движок (`DayTexts`, правила): `AddressForm` передаётся во вход плана, как `MentorPersona` |
| Контент YAML | `why_ru` — нейтральная форма, по желанию `why_ru_m` и `why_ru_f`. Проверка `scripts/check_*`: если в `why_ru` есть маркер мужского рода из словаря, проверка падает |
| Наставник (Claude) | в системный промпт передаём `address_form: m|f|n`. При `n` — правило «без прошедшего времени и кратких прилагательных о человеке» |

## Передача
- **Артефакт:** A53 (предлагаемый номер — A56, см. ⚑) · v0.1 · предложение, ждёт решений §6.
