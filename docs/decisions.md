### D-022 Энтерпрайз — это новый бэкенд, а не масштабирование MVP · 2026-11-06
Решение: архитектура MVP одноюзерная (allowlist по WHOOP `user_id`, ключи на устройстве, нет серверного состояния и аккаунтов). Переход к мультипользовательской и корпоративной версии означает новый серверный бэкенд: аутентификация, серверная identity, вероятно серверное хранение, организации, аудит, SSO. Утвердил: основатель. Пересмотреть: при старте этапа 1 или энтерпрайз-пилота.

### D-023 Политика версий метрик и правил · 2026-11-06 · предложение, ждёт подтверждения Агентов 3 и 9
Контекст: сырые данные WHOOP не хранятся (R-11), поэтому при смене формулы `metricId@ver` историю нельзя пересчитать из локальных данных. Решение (предложение):
1. Каждое значение хранится с версией формулы. Старые версии не удаляются и не переписываются.
2. Новая версия считается с даты внедрения. Если WHOOP API отдаёт историю за прошлые периоды и подписка активна, прошлое пересчитывается заново: загрузка в память, расчёт новой версии, сохранение только производных. Это нужно проверить (Агент 9).
3. Если пересчитать нельзя, на графиках показывается «шов» с пометкой о смене формулы. Тренды сравниваются только внутри одной версии.
4. Правила A09 тоже версионируются (`ruleId@ver`), в журнале дня записывается, какая версия сработала.
Последствие: формулы можно менять, история не ломается молча. Утвердили: основатель (запрос зафиксировать политику); детали ждут Агентов 3 и 9.

### D-024 Активность в MVP: WHOOP API + Health Connect (шаги телефона) · 2026-11-06
Контекст: A35. Без данных активности продукт фиксирует только восстановление: нельзя сверить план с фактом и учесть нагрузку. Pixel Watch основатель не носит. Решение:
1. Тренировки (вид, время, зоны пульса, strain, kJ) и шаги за сутки (`step_count`) берутся из WHOOP API. Нужны вебхук `workout.*` и опрос цикла днём.
2. Health Connect возвращается в MVP **как обязательная часть, но только для шагов телефона** (`READ_STEPS`, `READ_HEALTH_DATA_IN_BACKGROUND`, фильтр по data origin телефона). Данные WHOOP из HC не читаем, чтобы не было дублей.
3. Принцип сверки: нагрузку считаем по данным, исполнение — по отметке пользователя, без контроля (A35 §4).
4. Стресс в моменте — после MVP. В MVP есть «напряжение дня» (A35 §3).

Цена: около +3,5 дня Агента 13. Это уточняет D-011: HC в MVP только для шагов телефона, Pixel Watch — после MVP. Утвердил: основатель (карточка решения, «WHOOP + HC сразу»). Ревью: Агенты 10 (тексты), 7 (шаги HC, R-11), 5 (модель данных).

### D-025 Утренний пуш: «утро ведёт сервер» (A34, вариант B) · 2026-11-06
Контекст: A34. Вебхук WHOOP может потеряться или прийти дважды, а сетевая фоновая задача на телефоне под Doze ненадёжна. Решение:
1. С 04:00 до 12:00 по местному времени Worker каждые 3 минуты проверяет, готово ли восстановление. Вебхук запускает ту же проверку сразу.
2. Durable Object — единственный владелец refresh-токена WHOOP. Токен хранится зашифрованным (AES-GCM, секрет `TOKEN_ENC_KEY`). Телефон получает access-токен через `POST /whoop/access`.
3. Уходит один FCM high-priority пуш на `cycle_id`, не раньше 06:00. Внутри 5–6 чисел, зашифрованных ключом устройства. Телефон показывает «Карту дня» без сети.
4. Резервные пути: опрос с телефона и обновление при открытии приложения. Дедупликация по `dayKey`.

Метрики: L1 P90 ≤ 5 минут; доля «магических» утр ≥ 95 %. Пересмотр, если доля < 90 % за 2 недели.

Это уточняет D-019 и ADR-04. Worker по-прежнему не хранит данные о здоровье: восстановление он читает транзитно. Но теперь он хранит зашифрованный refresh-токен WHOOP. Цена: около +2 дня Агента 13. Перенос токена в DO — в И1.1, до среза 1. Утвердил: основатель (карточка решения). До реализации нужно ревью Агента 7 по хранению токена.

### D-026 Разбор фото, симптомов и анализов в v1: правила + Claude-помощник (A31 А′, A32) · 2026-11-06
Решение: в MVP разбор строится по архитектуре А′ из A31.
1. **Срочность** определяют детерминированные правила красных флагов в коде: «911 сейчас», «врач за 24–72 ч», «плановый визит», «наблюдать N дней».
2. **Claude** нейтрально описывает видимое, задаёт уточнения, даёт общий уход и готовит «кейс для врача» (PDF или текст).
3. Claude не ставит диагноз, не толкует результаты как триаж и не назначает лечение.
4. Gemini для медицинского модуля не берём.
5. MedGemma на устройстве — только эксперимент «для себя» после G2.
6. Внешние пользователи получают разбор только с врачом в контуре (архитектура Б).

Условие: до 12.11.2026 отправить запрос в Anthropic по новой AUP. Если ответ отрицательный, срочность определяется только чек-листом без фото, а Claude описывает и готовит вопросы врачу.

Утвердил: основатель (карточка решения). Ревью: Агенты 3, 7, 10 (красные флаги и тексты).

### D-027 Принцип «сначала данные, потом вопрос» · 2026-11-06
Решение основателя: продукт сам находит и понимает данные о пользователе и проактивно говорит, что делать, вместо того чтобы выспрашивать. Пользователь устаёт рассказывать и объяснять.

Правила:
1. Любой вход сначала выводится из данных: WHOOP (сон, тренировки, шаги), телефон (будильник, календарь, шаги, часовой пояс), наша собственная история.
2. Вопрос допустим только как подтверждение в один тап при низкой уверенности. Без открытых вопросов и ввода текста, не чаще одного раза в день вне вечерней колоды.
3. Настройки показывают выведенные значения с подписью источника. Ручная правка побеждает вывод.
4. Самоотчёты (энергия, пик напряжения) остаются только там, где данных нет в принципе. Цель вечерней колоды — не больше 3 тапов.

Первое применение — якоря распорядка в A09 §7a. Касается также A19, A25 и онбординга (Агенты 4, 10 и 12 проверяют, где ещё есть вопросы, которые можно заменить данными). Новое разрешение — `READ_CALENDAR`. Утвердил: основатель.

### D-028 Фирменный знак v2 и визуальный язык «Колоннада» · 2026-11-06

### D-029 SOS уходит из шапки, на его месте три кольца статуса · 2026-11-06
Решение основателя по анализу аналитика и дизайнера (Агенты 2 и 4). Постоянная кнопка SOS в шапке каждой вкладки снимается.

Почему: в Wysa кризис был у 5,2 % пользователей, 82 % из них распознал ИИ и только 18 % отметили сами, то есть кнопку нажимает около 1 % в год. Лидеры (WHOOP, Oura) ставят наверх главные метрики, а ChatGPT и Character.ai показывают 988 только при детекции. Законы CA SB 243 и Нью-Йорка требуют детекцию кризиса и направление к помощи, постоянная кнопка не обязательна.

Обязательный минимум (красная линия, не обсуждается):
1. Офлайн-детекция CrisisGuard в чате наставника, вечернем чек-ине и голосе с автопоказом трезвой карточки 988/911.
2. Раскрытие «я ИИ», отказ от вредного контента, опубликованный кризисный протокол до тестеров.
3. Тихий вход в помощь не дальше 2 тапов: «Я › Помощь», «⋮ › Помощь» в чате. Плитка быстрых настроек и ярлык иконки остаются.

Шапка: три тонких кольца — нагрузка против потолка режима, шаги против цели, время до отбоя. Все значения выводятся из WHOOP и телефона без ввода (D-027). Калории не показываем: съеденное не считаем (A19, вето Агента 3), это отдельное решение. Вид колец — по новой визуальной концепции (A37, в работе).

Последствия: A11 §1, §1.3, §8.1; A18 И0.4 и чек-лист приёмки; A36 (SOS). Тексты кризисной карточки не меняются; ревью Агентов 10 и 7 — на новые точки входа. Утвердил: основатель (карточка решения).

### D-031 Визуальная концепция «Титаниум» вместо «Колоннады» · 2026-11-06
Решение основателя: принять концепцию «Титаниум» (A37 v0.2). Она заменяет визуальный язык «Колоннада» (A36, D-028); знак v2 не меняется.

Суть: Титан из знака v2 — герой каждого главного экрана, технологичность — материал вокруг него (свет, стекло, точность). Синхронизация «Титан приходит» (выходит из тумана и раздвигает колонны), «Рассвет» с хокку состояния и настроя на день, камера-трафарет с контуром Титана для фото тела, «Твой Титан» по шести сферам, пиктограммы вместо подписей, шапка из трёх колец (D-029). Шрифты Geist и Geist Mono (OFL); Cormorant остаётся только в вордмарке стора и сплэша.

Последствия: A36 заменяется A37; токены и компоненты переезжают в `:core:ui` (Агенты 5 и 13); анимация синхронизации из `HotSyncMark` получает новую `SyncMarkArt`.
